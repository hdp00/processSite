# 流程定义与流程运行全生命周期测试报告

> 架构变更说明（2026-08-26）：本报告是前端原型历史测试证据，正文中的 NestJS 代表当时目标。当前正式后端目标已切换为 .NET 10 / ASP.NET Core 10；历史测试结果仍不能代表生产后端验收。

> 测试日期：2026-08-19  
> 测试对象：FlowPilot 公司内部流程审核平台原型  
> 测试结论：核心生命周期通过；本轮发现的 2 个阻断性数据问题已修复并回归通过。

## 1. 测试范围

### 1.1 流程定义

- 新建独立流程定义并生成正式 V1。
- 保存基本信息、初始表单和流程拓扑，自动更新校验结果。
- 校验未通过时禁止发布。
- 发布首个版本，以及从任意版本复制新建下一版本。
- 切换发布版本，确保一个流程定义最多只有一个发布版本。
- 复制新建完整流程定义，确认生成新的定义、正式 V1 和独立快照，且不自动发布。
- 取消发布、删除未发布零实例版本、删除最后一个版本和流程定义。
- 阻止删除发布版本、已有实例版本和已有实例的流程定义。
- 阻止无配置权限用户创建、复制或发布流程。
- 停用、启用与无发布版本时的新实例创建限制。

### 1.2 固定审批流程

- 使用当前发布版本创建实例并生成共享前缀编号。
- 发起时指定默认审核人并生成并行待办。
- 首个审核结果产生前修改发起表单；产生结果后锁定。
- 非创建人修改、非授权人员审核、错误节点处理方式和无意见驳回均被拒绝。
- 审批通过、确认、驳回、并行待办取消、重新提交和新轮次待办重建。
- `重新提交或关闭`、`仅允许重新提交`、`自动关闭流程`三种驳回处理结果。
- 条件不满足节点自动跳过，并参与汇聚完成判断。
- 超级管理员跨权限组处理并记录实际处理人和代办标识。
- 全部节点通过后实例进入已完成，审批按钮消失。
- 关闭权限、重复关闭和已锁定版本继续运行。

### 1.3 自由协作流程

- 创建、回复、转交下一受理人、异常改派、关闭和填写理由后重新打开。
- 非参与人员不能回复；受理范围和关闭权限继续按锁定版本判断。

## 3. 浏览器实际操作结果

浏览器中以超级管理员身份完成以下完整链路：

1. 新建“全面测试流程 0819”，填写基本信息并生成 V1。
2. 进入初始表单和流程设计步骤；审批节点未配置权限组时，发布页明确显示校验问题并禁用发布。
3. 从 PDF 文件审核 V3 复制生成 V4，完整表单和三节点并行拓扑正确带入。
4. 发布 V4，原 V3 自动退出发布，新发起入口显示 V4。
5. 从流程定义概览执行“复制新建流程”，生成新的流程定义、V1 和独立 UUID，未复制历史实例。
6. 发起 `DOC26080044`，指定研发、质量、生产默认审核人，提交后返回流程发起页，并在任务中心生成 3 个待办。
7. 空意见驳回被阻止；填写意见后驳回成功，其余并行待办立即取消。
8. 重新提交后生成新一轮全部待办，流程实例编号和锁定版本保持不变。
9. 再次驳回并重新提交后，时间线分别展示原始“流程发起”、历史审核、第 3 轮重新提交人和真实提交时间。
10. 研发、质量、生产依次通过后，流程状态变为“已完成”，当前节点为“流程结束”，不再显示审核按钮。

浏览器控制台未发现运行时异常。页面存在 Ant Design 6 的弃用提示，包括旧版 `Tag.bordered`、`Card.bordered`、`Timeline.items.children` 和静态 `message/Modal` 上下文提示；它们不影响本轮业务操作，但建议在后续技术债清理中统一升级。

## 4. 本轮发现并修复的问题

### 4.1 快速连续创建可能产生重复流程定义 ID

原实现只使用 `Date.now()` 生成流程定义 ID，同一毫秒内连续新建或复制会得到相同标识。现已统一改用 HTTP 兼容的 `createClientUuid()`：安全上下文优先使用 `crypto.randomUUID()`，普通 HTTP 使用 `crypto.getRandomValues()` 生成 UUID v4，并保留最终防碰撞降级；同时增加固定时间下连续创建的回归用例。

### 4.2 重新提交错误覆盖首次发起时间线语义

原详情页进入第 2 轮后，会把首次创建记录显示成“第 2 轮发起”，且时间仍是最初创建时间。原运行态也没有保存独立的重新提交事件。

现已为实例增加重新提交记录，保存轮次、提交人、提交时间和修改字段标识/名称，并同步用于：

- 流程详情时间线；
- 打印流转记录；
- 运行时审计日志。

首次创建始终显示为“流程发起”，后续轮次按实际重新提交时间独立显示。

## 5. 结论与剩余风险

流程定义的创建、配置、复制、发布、切换和删除保护，以及固定审批流程的创建、修改、审核、驳回、重新提交、条件跳过、确认、完成和关闭逻辑均已通过自动化回归。自由协作流程的核心流转也已通过。

当前仍是本地交互原型。真实 NestJS 后端、SQL Server 事务、并发提交、邮件发送、文件持久化和数据库迁移尚未接入，因此本报告确认的是前端领域模型和原型运行链路，不代表生产后端的并发与持久化能力已经验证。
