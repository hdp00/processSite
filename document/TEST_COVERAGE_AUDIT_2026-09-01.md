# FlowPilot 测试覆盖审计（2026-09-01）

## 1. 审计结论

本次“自由协作仅变更受理人返回 500”暴露出此前测试结论不够严谨：前端 Store 和 MSW 已覆盖自由协作操作语义，但真实 SQL Server 测试没有逐个调用回复、改派、编辑回复、关闭和重开命令。因此，测试无法发现新待办与邮件队列的外键写入顺序，也无法发现 EF 更新带触发器表时的 SQL 兼容问题。

以前报告中的“自由协作发起、回复、变更受理人、关闭、重开”应理解为前端 Mock 业务链路覆盖，不能作为真实后端数据库链路已经覆盖的证明。本轮已补齐相关真实数据库测试，并将报告口径改为按测试层级分别列证据。

## 2. 本次缺陷与修复证据

| 场景 | 原有证据 | 原有缺口 | 本次新增或修正 |
| --- | --- | --- | --- |
| 仅变更受理人 | 前端 Store 测试 | 未调用真实后端命令，未提交真实事务 | 真实 SQL Server 调用改派命令；核对旧待办完成、新待办待处理、唯一当前受理人、时间线、通知和幂等重放 |
| 回复并变更受理人 | 前端 Store 测试 | 同上 | 独立 SQL 分支用例，核对回复与改派两条时间线 |
| 发起/受理权限组改派 | 前端权限测试 | 未验证后端锁定版本权限组 | 分别由非发起人的发起权限组成员和受理权限组成员执行真实改派 |
| 编辑回复 | 前端 Store 测试 | 未发现时间线表触发器与 EF `OUTPUT` 不兼容 | 真实 SQL 更新并核对最新正文、编辑元数据和编辑审计事件 |
| 关闭后重开 | Outbox Writer 独立测试 | 未执行创建新待办与通知的完整命令 | 真实 SQL 关闭、重开，核对任务、时间线和两类通知 |
| 驳回后重新提交 | 前端 Mock 生命周期 | 原 SQL 生命周期直接通过，未走驳回/重提 | SQL 生命周期改为驳回、生成重提任务、重新提交、第二轮审核 |
| 审核字段 | 前端状态测试 | SQL 生命周期未提交授权字段 | SQL 审核提交授权字段，并在完成后验证允许重复修改 |
| 审核前修改 | 前端状态测试 | SQL 生命周期未调用修改发起内容命令 | SQL 生命周期在首次审核前修改表单并继续后续链路 |

## 3. 当前后端业务写操作矩阵

| 范围 | 真实 SQL 成功路径 | 主要边界证据 |
| --- | --- | --- |
| 流程定义 | 创建、保存表单、保存流程、发布 | 过期 revision、配置校验、锁定版本 |
| 固定审批 | 发起、审核前修改、驳回、重新提交、通过、重复修改授权字段 | 并发标识、授权字段白名单、幂等、通知收件人 |
| 自由协作 | 回复、仅改派、回复并改派、编辑回复、修改初始表单、关闭、重开 | 发起/受理权限组、无权用户、无效/未变化受理人、过期 revision、幂等、唯一待办 |
| 邮件 | 任务激活、自由协作当前受理人、完成/关闭通知 | 测试邮箱覆盖、空业务邮箱、任务外键和收件人 |
| 组织与导出 | 用户最近登录、Excel 实例编号 | 真实数据库读取与写入 |

固定审批“主动关闭”、真实附件上传/读取、LDAP、SMTP 实际投递、IIS 和远程浏览器链路仍属于独立验收项，不能由本地 SQL 或 Mock 测试冒充。它们不影响本次缺陷修复，但后续报告必须继续明确标记层级和执行环境。

## 4. 防止同类遗漏的执行规则

1. 新增或修改后端命令时，先列出所有可选字段形成的独立分支，再为每个有不同副作用的分支建立真实 SQL 用例。
2. 凡是同时写任务、时间线、审计、附件引用或邮件队列，测试必须提交完整事务并逐表核对最终状态。
3. 带触发器、计算列、复合外键或只追加约束的表，不允许只用 Mock、EF InMemory 或纯映射测试验证。
4. 测试报告按“前端领域/Mock、HTTP 契约、真实 SQL、浏览器 Mock、浏览器 Remote、部署环境”分别给出结果；未执行就明确写未执行。
5. 每次用户现场发现缺陷，都要把复现路径加入回归矩阵，而不是只增加针对某个辅助函数的测试。
