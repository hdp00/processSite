# FlowPilot 代码与测试审查报告

审查日期：2026-09-01  
审查范围：前端生产代码、ASP.NET Core 后端、SQL Server 数据访问、REST/OpenAPI 契约、构建与测试配置、全部自动化测试及当前规范文档。

## 1. 结论

本轮已完成浏览器 Mock、MSW、IndexedDB 及其他浏览器业务持久化的移除。系统当前只有一个业务事实来源：ASP.NET Core 后端、SQL Server、后端附件目录和邮件 Outbox。Zustand 仅保存当前页面生命周期内的查询缓存，刷新后重新从后端读取；认证只使用同源 HttpOnly Cookie。

审查发现的可自动修复问题均已修复。最终 `pnpm test:all` 完整通过，未发现剩余的 P0/P1/P2 代码缺陷或失败/跳过测试。本轮没有增加第三方库，移除了 `msw`、`@mswjs/interceptors` 和 `fake-indexeddb` 直接依赖。

## 2. 主要整改

### 2.1 单一后端数据源

- 删除 `apps/web/src/mocks`、前端 Mock 数据、浏览器附件仓储、IndexedDB 富媒体仓储、本地审计、浏览器身份和编号序列等实现。
- 删除 Mock 专用 REST handlers、运行模式分支、演示数据重置、Bearer 原型令牌以及 localStorage/sessionStorage 持久化。
- 开发、Debug、E2E 和生产统一请求 `/api/flowpilot/v1`；本地 Vite 仅代理真实 ASP.NET Core API。
- 页面所有业务请求继续集中经过 `flowPilotApi` 和统一客户端；静态检查只发现统一客户端内部的两个 `fetch` 实现，没有页面绕过客户端直接请求。
- 列表、任务、流程详情、治理页面和权限判断改为使用后端返回的数据与能力字段；详情/打印路由每次打开都重新请求后端，避免把不完整列表缓存当成已授权详情。

### 2.2 富文本图片和视频

- 富文本工具栏上传改为 `purpose=rich-text-media` 的后端附件上传，不再生成或保存 Blob URL、Base64 或 IndexedDB 文件标识。
- 正文只保留后端附件 UUID、`data-attachment-id` 和同源受认证内容地址；读取和保存前均进行 HTML 净化，外部地址、浏览器临时地址和非法标识会被移除。
- 后端按内容签名识别 PNG、JPEG、GIF、MP4 和 WebM，声明为图片/视频但签名不匹配时按 415 拒绝；媒体允许认证后的内联读取。
- 富文本媒体上传成功后作为长期 `active` 资产保存，不能通过暂存附件删除接口误删，避免已保存正文出现失效图片或视频。
- 当前简化设计不建立正文级媒体引用表。因此取消编辑后已经上传但未引用的媒体不会自动回收，且所有已登录用户可凭不可预测 UUID 读取媒体。这是面向内部小型站点的明确取舍；以后若需要孤儿清理或实例级读取范围，必须先增加服务端正文引用表，不能恢复浏览器存储。

### 2.3 并发、会话和前端稳定性

- 并行浏览器登录发现会话写锁与“最近登录时间”聚合读取发生 SQL Server 死锁。最近登录时间只是展示字段，查询已改为不参与业务一致性的 `READUNCOMMITTED` 读取；四个 Chromium worker 并行回归后未再出现死锁。
- 退出登录会先取消统一客户端中仍在进行的业务请求并立即清理内存会话，再调用后端注销，避免并发列表请求在 Cookie 失效后产生 401 竞态。
- 后端已确认会话有效但基础目录临时加载失败时，前端不再错误注销用户；业务页面可以按需重试。
- Ant Design 静态消息调用全部迁移到应用上下文，Drawer/Button 废弃属性已更新；对应组件测试也补齐真实 `App` 上下文。
- 任务中心横向滚动区域增加键盘焦点和可访问名称，axe 的 serious 级问题已消除。

### 2.4 文档与配置

- 删除 `document/MOCK_REST_API.md`，并同步 README、AGENTS、需求、测试策略、后端设计、IIS 部署和 OpenAPI。
- 删除 IIS 文档中残留的 `build:web_mock` 说明和需求中残留的“浏览器附件存储”规范。
- 旧 Mock 变更记录只作为历史记录保留，不代表当前运行方式。
- `pnpm-lock.yaml` 中仍可能出现 `msw` 文本，它只是 Vitest 自身 `@vitest/mocker` 声明的可选 peer 名称；锁文件中不存在 `msw@`、`fake-indexeddb@` 或 `@mswjs/interceptors@` 包条目，本地安装目录也不存在这些包。手工删除上游可选 peer 元数据会破坏锁文件的可重复生成，因此没有篡改。

## 3. 测试代码审查

### 3.1 删除和保留原则

- 删除以浏览器 Mock 数据、固定演示身份、固定流程 ID 或 localStorage/IndexedDB 为测试事实来源的集成与 E2E 用例；这些用例只能证明第二套前端业务实现，不能证明正式后端可用。
- 保留纯函数、DTO 适配、组件交互和权限计算测试。Vitest 中的 `vi.mock`、网络函数替身和 DOM Observer 替身只用于隔离组件边界，不提供运行时业务数据，也不会进入生产包。
- 流程定义、发布、发起、审批、自由协作、邮件、附件引用、事务、并发和数据库迁移继续由真实实现及正式 Migration 的 .NET/SQL 测试覆盖。
- 浏览器测试默认构建 Debug API，在独立端口 `3100` 启动编译产物并连接真实数据库；不复用开发者可能正在运行的 3000 端口服务。

### 3.2 新增或调整的回归验证

- 禁用 localStorage、sessionStorage 和 IndexedDB 后，仍可通过真实后端登录并进入任务中心。
- 富文本媒体真实上传、认证读取、活动媒体禁止误删、伪装图片签名拒绝。
- 超级管理员的用户、部门、角色、权限、流程权限组、流程管理、实例监控和审计页面全部从后端加载。
- 真实 Cookie 会话刷新保持、退出清理和在途请求取消。
- REST 客户端不发送 Authorization/Bearer，且可统一取消在途请求。
- 登录页和任务中心无 critical/serious WCAG A/AA 问题；登录页保留不依赖可变业务数据的视觉基线。
- 可访问性失败报告现在包含具体 DOM target，后续定位不再只有规则名称。

### 3.3 测试质量检查

- 未发现 `.only`、`@ts-ignore`、TODO/FIXME/HACK 或零测试程序集。写入业务数据的 Playwright 链路仅在自动隔离的本地数据库中运行；指向已部署服务时使用条件 `test.skip`，避免自动化污染远端数据。
- E2E 优先使用角色、可访问名称和用户可见标题定位；预期 401 的忽略规则只覆盖未登录会话探测和错误密码登录，不会吞掉其他接口的授权错误。
- 浏览器用例独立 BrowserContext、并行运行；写入型 SQL 生命周期测试使用独立临时数据库或受控数据范围。
- 核心前端覆盖率门禁保持高覆盖；全源码报告单独显示页面代码缺口，不用大量 jsdom 页面调用替代真实浏览器和 SQL 链路。
- 该缺口已修复：本地 Playwright 从开发配置派生安全命名的专用数据库和附件目录，测试开始前重建并初始化，结束后即使失败也清理；API 与数据库工具使用独立测试构建目录，不覆盖或停止 `dotnet watch`。删除数据库前会再次验证 `_PlaywrightTests_<API 端口>` 后缀。已在 Chromium 中实际验证创建、登录、固定审批写链路、自由协作仅改派和最终清理。

## 5. 仍需部署环境验收的项目

以下不是当前代码缺陷，自动化环境也不能代替现场验收：

- 使用公司实际 LDAP/LDAPS 账号验证成功、错误密码和域服务不可用场景。
- 使用实际 SMTP 配置验证测试邮箱覆盖、投递、重试和死信处理。
- 在目标 IIS/ARR、Windows Service、正式 Host 绑定和代理头配置下执行部署冒烟与重启/回滚。
- 在实际计划部署的 SQL Server 版本、兼容级别、排序规则、备份与恢复策略上再次执行数据库验收。
- 根据真实存储增长量决定是否需要为富文本媒体增加服务端引用表和孤儿清理；首版不会自动删除这类长期媒体。

## 6. 历史缺陷后的测试缺口复核

后续实际使用连续发现了页面调用和展示问题，因此第 1 节“未发现剩余问题”的表述只能理解为当时门禁没有失败，不能理解为业务链路覆盖已经完善。全源码报告中多数流程页面覆盖率为 0，现有真实浏览器用例也偏向登录、页面可打开和附件上传；SQL 领域链路通过不能替代页面是否传递 ETag、是否使用服务端能力字段或是否正确切换筛选的验证。
