## 2. 覆盖范围

### 单元与领域逻辑

- 角色权限、动作权限、路由权限、超级管理员边界和当前会话权限。
- 流程权限组的直接成员、角色派生成员、停用用户/角色、用途过滤和未知引用。
- 流程版本解析、草稿/发布版本选择、复制、发布、停启用、删除保护和旧数据迁移。
- 流程实例、任务、轮次、节点、通知和身份引用的数据一致性。
- 流程定义校验、设计器持久化、损坏 JSON、旧 schema、SSR 和 IndexedDB 边界。

### 组件与界面逻辑

- 登录必填、错误凭据、成功跳转和演示身份选择。
- 未登录路由保护、角色入口限制和无权限结果页。
- 流程向导上一步/下一步按钮、禁用状态和导航回调。
- 键盘可达性、表单反馈、按钮/弹窗交互、页面标题和主要路由加载。

### 数据与 Mock API 契约

- 6 项领域数据完整性测试：唯一标识、跨实体引用、双向成员关系、迁移和持久化边界。
- 8 项 API 边界测试：Problem Details、分页/过滤、鉴权、重置授权、ETag、幂等上传、附件读取和删除授权。
- 附件生命周期覆盖重复上传去重、IndexedDB 单记录、元数据/内容读取、非上传人 403 和上传人 204 删除。

### 端到端业务链路

- 未登录拦截、错误登录、正确登录和刷新后会话保持。
- 只读身份、审核身份、超级管理员的菜单、直达路由和动作权限。
- 普通用户看不到重置入口；当前演示身份或真实操作者为超级管理员时显示入口，但接口始终按真实操作者决定是否允许执行。
- 超级管理员顺序遍历 16 个主要路由，并验证无 403、无错误提示。
- 自由协作事项发起、首位受理人校验、创建成功、列表查询和刷新持久化。
- 驳回意见必填和实际驳回操作。
- 完整固定流程：王敏发起 PDF 审核 → 林晓驳回 → 王敏第二轮重新提交 → 张伟、林晓、赵磊三个并行节点通过 → 实例完成。

## 3. 本轮发现并修复的问题

| 级别 | 问题 | 修复与回归 |
| --- | --- | --- |
| P1 | 停用角色仍可能通过流程权限组关联扩散有效成员 | 有效成员只合并启用角色；停用用户仍被排除。保留“权限组停用只阻止新引用、不影响既有发布/运行实例”的需求语义，并新增回归测试。 |
| P1 | 流程定义 v16 旧数据迁移曾把停用状态和发布指针错误绑定，可能丢失“已停用但已取消发布”的合法状态 | 迁移时独立保留 `disabled`，同时清理悬空发布指针；新增停用后取消发布及旧数据迁移回归测试。 |
| P1 | 登录页和应用壳层的演示身份下拉框缺少可访问名称 | 增加明确的中文 `aria-label`，axe 的 `label` critical 问题清零。 |
| P1 | 登录、任务中心和发起中心多处次要文字对比度低于 WCAG AA | 在页面作用域内加深次要文本颜色；axe 的 `color-contrast` serious 问题清零。 |
| P1 | Mock“重置演示数据”接口只读取可选请求身份，匿名、普通用户或仅切换前端演示身份存在越权重置风险 | 接口现在要求有效会话，并按真实登录操作者校验唯一内置超级管理员；补充匿名、普通用户、伪装切换和超级管理员模拟普通身份的契约及界面测试。 |
| 测试稳定性 | 本机同时运行 6 个重页面用例时，长业务链路、axe 扫描或整页截图偶发超过 30 秒，但最终状态和断言均正确 | 本地并发固定为 4，通用浏览器预算为 60 秒，完整审批闭环为 120 秒；未更新视觉快照，并在该配置下执行最终全量复验。 |

## 4. 未执行项与剩余风险

当前仓库是前端交互原型，没有正式 NestJS 服务、真实认证、数据库或文件存储，因此以下项目本轮状态为“未执行”，不能由 Mock 测试结果替代：

- SQL Server 2016 SP2、数据库兼容级别 130 下的迁移、约束、事务回滚和一致性测试。
- 多请求真实并发、任务抢占、幂等键竞争和数据库隔离级别测试。
- 附件落盘、病毒扫描、断点/失败恢复、备份恢复和容量测试。
- SMTP、Outbox、后台任务和服务重启后的恢复测试。
- 生产鉴权、密钥、TLS、安全扫描、负载、长稳和灾备测试。

非阻断改进项：全源码单元覆盖率仍有较大提升空间，尤其是治理页面、设计器页面和 Mock handlers；这些区域已有浏览器链路覆盖，后续应按变更风险逐步补充组件或领域测试，而不是用低价值渲染用例堆高数字。

## 5. 交付物与复现命令

- 测试策略：`document/TEST_STRATEGY.md`
- 核心覆盖率 HTML：`apps/web/coverage/core/index.html`

从仓库根目录执行：

```bash
pnpm test
pnpm test:coverage
pnpm test:coverage:all
pnpm typecheck
pnpm build
pnpm test:e2e
pnpm test:e2e:edge
```

`pnpm test:all` 会按顺序执行类型检查、两类覆盖率、production/debug 双构建、Chromium 全量和 Edge 冒烟门禁。
